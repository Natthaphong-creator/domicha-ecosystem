# DomiCha Stock V2

ระบบคลังชุดใหม่แยกจากระบบบัญชีเดิม ใช้ GitHub เก็บโค้ดและ Firebase Hosting เผยแพร่เว็บ ไม่ใช้ Netlify

## เปิดทดลอง

```sh
cd stock-v2
npm ci
npm run dev
```

เปิด URL ที่แสดง แล้วเลือก **เปิดระบบทดลอง** ใช้ข้อมูลสาธิต 12 รายการ บันทึกใน Local Storage เฉพาะเบราว์เซอร์นี้ ไม่เชื่อมข้อมูลเดิม โหมดนี้ไม่ใช่การยืนยันตัวตนหรือระบบใช้งานจริง

มีค้นหา กรองหมวดหมู่/จุดสั่งซื้อ รับเข้า เบิกออก ประวัติ และส่งออก CSV จำนวนต้องเป็นจำนวนเต็มบวก และห้ามเบิกเกินยอด คำเตือนจุดสั่งซื้อรวมกรณียอดเท่าขั้นต่ำ แยกหน่วยต่อสินค้า ไม่บวกรวมกระป๋องกับแพ็กเป็นยอดเดียว

## เชื่อม Firebase สำหรับใช้งานจริง

1. สร้าง Firebase project แยกสำหรับ V2 และเปิด Firestore กับ Authentication แบบ Email/Password
2. ใส่ Web App config ใน `public/firebase-config.json` (apiKey, authDomain, projectId, appId) ค่า config นี้เป็น public client configuration ไม่ใส่ service account หรือรหัสผ่าน
3. สร้างบัญชีใน Authentication ผ่าน Console แล้วเพิ่มเอกสาร `users/{uid}` มี `name` (ข้อความ) และ `role` (`owner` หรือ `staff`) ชื่อต้องไม่ว่าง
4. เพิ่ม `products/{id}` ผ่าน Console โดยมี `name`, `category`, `unit` เป็นข้อความ และ `stock`, `minimum` เป็นจำนวนเต็มไม่ติดลบ เช่น `{"name":"ชาแดง","category":"ชา","unit":"ถุง","stock":12,"minimum":4}` ใช้ ID ที่ไม่มี slash
5. ทดสอบ Firestore Rules ด้วย Emulator ก่อนเผยแพร่จริง กติกาปฏิเสธผู้ไม่มีบัญชี/สิทธิ์ บัญชีพนักงานสร้างโปรไฟล์ตัวเองไม่ได้ และเปลี่ยนยอดได้เมื่อมีประวัติใหม่ในธุรกรรมเดียวกัน ประวัติแก้ไขหรือลบผ่าน client ไม่ได้
6. ติดตั้ง Firebase CLI จากแพ็กเกจทางการและเข้าสู่ระบบด้วยบัญชีเจ้าของ ตั้ง authorized domain ให้ตรงเว็บที่ใช้
7. รัน `npm run build` และ `firebase deploy --project YOUR_NEW_PROJECT_ID --only hosting,firestore:rules`

การเผยแพร่ Rules ควรใช้โปรเจกต์ใหม่เท่านั้น ไฟล์นี้ไม่ได้ออกแบบให้แทนที่ Rules ของระบบเก่าโดยตรง ต้องมีสิทธิ์บัญชี Firebase ก่อนจึงเปิดระบบออนไลน์จริงได้

## การตรวจสอบ

`npm test` ตรวจยอดรับเข้า/เบิกออก ขอบเขตจำนวน จุดสั่งซื้อ และการ escape ข้อความ
`npm run build` สร้างเว็บลง dist

ยังต้องทดสอบกับ Firebase Emulator/บัญชีจริง: สิทธิ์บุคคลทั่วไป บัญชีที่ไม่มีโปรไฟล์ การเขียนยอดโดยไม่มีประวัติ การแก้ประวัติ และการเบิกพร้อมกัน 2 บัญชี ก่อนเปิดใช้งานจริง

## ขอบเขตรุ่นแรก

คลังกลางหนึ่งแห่ง ยังไม่มีโอนสาขา เพิ่ม/แก้รายการสินค้าผ่าน UI อนุมัติรายการ หรือย้ายยอดเก่าอัตโนมัติ ประวัติคลาวด์รุ่นนี้โหลดทั้งหมดจึงควรเพิ่มการแบ่งหน้าเมื่อข้อมูลมากขึ้น โหมดทดลองไม่ใช่ข้อมูลสำรองและไม่แชร์ข้ามเครื่อง
